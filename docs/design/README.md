# 設計

このプロジェクトの責務・処理・判断条件を調べる入口である。
方針の合意範囲と採用理由は [ADR](../adr/README.md) を参照する。
設計文書は、合意済みの範囲と設計案を区別して書く。

## 全体を理解する

[全体像](../overview.md) → [責務と依存方向](architecture.md) が共通の読み順である。
機構別の設計は、調べたい機構が決まってから読む。
方式を選ぶ前と、機構を追加・変更する前には、[設計の原則](principles.md) を読む。

## 機構を調べる

機構別の設計文書を追加したら、次の形式で表へ加える。
各行の「最初に読む」で処理の全体をつかみ、必要な詳細へ進めるようにする。

```markdown
| テーマ | 最初に読む | 必要な詳細 |
| --- | --- | --- |
| テーマ名 | [処理の全体](機構.md) | [詳細契約](詳細.md) |
```

まだ機構別の設計はない。

設計文書の構成と書き方は [執筆・編集ガイドライン](../development/documentation-guidelines.md) に従う。
