# 全体像

このリポジトリで開発するものの目的・対象・主要概念を、初めて読む人に向けて説明する文書である。
要件・合意済み方針・設計案・未決事項を区別して読めるよう、詳細は各定義元へリンクする。

**現在の段階は [開発計画](development/plan.md#段階別の進め方) を参照する。**

初めて読む場合は、次の順に進む。

1. この文書で、目的と主要概念を把握する。
2. [要件と受入条件](requirements/catalog.md) で、実現することと受入条件を確認する。
3. [設計](design/README.md) で、責務と処理の全体を確認する。

## 目的

何を実現するか、誰が使い、使うと何が変わるかを書く。

## 対象と境界

このプロジェクトが扱うものと扱わないもの、外部の製品・人・組織との境界を書く。

## 主要な概念

設計・要件で繰り返し使う概念を、共通の具体例で導入する。
名前は以後の文書でも同じ表記に揃える。

## 通常の流れ

要求の受付から結果の確認までの通常の流れを、利用者が見る情報・行う操作・得る結果の順に書く。

## 自律性の境界

自動で進める範囲と、人の確認・承認を必要とする範囲を書く。
自動で進める処理を持たないプロジェクトでは、この節を削除する。

## 完成の定義

何をもって完成とするか、確認の方法と合わせて書く。
