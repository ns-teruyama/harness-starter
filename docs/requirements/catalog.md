# 要件と受入条件

このプロジェクトに必要な要求と、それを検証できるようにする受入条件の一覧である。
各項目では、要求と受入条件を読み、実現方式は「設計・運用」、確認方法は「検証」の参照先へ進む。
受入条件で明示した値以外の測定閾値は未決として扱う。

合意済みの方針と採用理由は [ADR](../adr/README.md)、未選定の方式・数値は [開発課題](../development/issues/index.md)、実装の順序は [開発計画](../development/plan.md) で確認する。

## ID の規則

- 機能要件は `FR-001`、非機能要件は `NFR-001` からの連番とする。
- ID は再利用せず、別の意味へ付け替えない。不要になった要件は、理由を残して廃止と記す。
- 要件を変更したら、依存する設計・受入条件・運用文書への影響を点検する。
- 文書間の参照は、ID とこの文書の該当見出しへの直接リンクで行う。

## 機能要件の索引

まだ要件はない。
要件を追加したら、次の形式で索引の表へ1行ずつ加える。

```markdown
| ID | 要求 | 分類 |
| --- | --- | --- |
| [FR-001](#fr-001) | 要求を一文で書く | 分類名 |
```

## 機能要件

各要件は次の形式で書く。
見出しを ID だけにすると、`#fr-001` の形で安定したリンク先になる。

```markdown
### FR-001

**要求を一文で書く**

受入条件を、検証できる形で書く。

設計・運用: [設計文書の名前](../design/設計文書.md)

検証: ケースID（[検証の索引](../development/verification/README.md)）
```

## 非機能要件

非機能要件も、`### NFR-001` の見出しで同じ形式に書く。
索引の表は、機能要件の索引と同じ形式で、この節の冒頭に置く。
