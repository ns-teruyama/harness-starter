# 記録（レビュー・調査・検証の結果）

保存を求められたレビューの指摘と、調査・試作・検証で確かめた結果を、日付ごとに置く。
記録はその時点の観測と対応を残すものであり、現在の仕様の定義元にはしない。

- 結論は要件・設計・ADR などの定義元へ反映する。
- 未対応の指摘や残る問いは [開発課題](../issue-management.md) として登録する。
- 記録で課題を完了にした場合は、課題の確認結果からその記録へリンクする。

## 一覧

まだ記録はない。
追加したら、ファイルへのリンクと、確かめた内容を1行ずつ書く。

## 書き方

ファイル名は `YYYY-MM-DD-主題を表す英語名.md` とする。
試作コードや結果の JSON など、記録の根拠となるファイルは、同じ日付の接頭辞を付けて並べて置く。
秘密情報、実運用の未加工ログ、資格情報は保存しない。

```markdown
# 記録の主題

YYYY-MM-DD の結果。結論を先に書き、反映先（ADR・課題など）へリンクする。

## 対象と条件

レビューなら照合した要件と経路を、調査・検証なら対象の版、環境、試作コード、実施した項目を書く。

## 結果

| 見つかったこと | 対応 |
| --- | --- |
| 問題や観測を、操作順と期待結果が分かるように書く | 反映先と、登録した課題 ID を書く |

期待した観測が成立したことと、互換性・品質の合格とを区別する。

## 確認できなかったこと

未確認の範囲と、その理由・次に確かめる条件を書く。
```
